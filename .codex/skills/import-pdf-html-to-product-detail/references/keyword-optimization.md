# 产品 PDF HTML 关键词优化规则

## 目标

在不改变技术事实的前提下，让同一产品详情内的术语、主关键词和相关内链保持一致。关键词 CSV 是研究证据，不是无条件替换词典。

## 1. 确定主关键词文件

从产品栏目、URL、产品名称和模型字段判断产品类别，再选择：

`docs/关键词列表/按产品系列类型拆分/<Volume>-<Count>-<类别>.csv`

示例：

- URL 包含 `air-vents-and-air-eliminators`，产品为 AE30 液体系统自动排空阀。
- 主文件使用 `40-80-排空气阀.csv`。
- 用 `AE30`、`air vent`、`air release valve`、`排空气阀`、`自动排空阀` 等表达查找候选词。

主文件没有合适候选词时，使用 `rg -i` 搜索整个拆分目录，但必须确认其他 CSV 中的词仍与当前产品真实类型一致。找到关键词后直接读取其 `内链` 列；空值是“具体型号尚无详情页”的显式状态，不要自行回退到类别链接。

## 2. 为每种语言建立独立计划

每种语言至少记录：

| 概念 | 原表达 | 规范表达 | CSV 来源 | 意图/Volume | 内链目标 | 处理理由 |
|---|---|---|---|---|---|---|

选择规则：

- 产品型号词优先于泛品类词，前提是与当前型号一致。
- 同等相关性下，优先使用有明确 Intent、较高 Volume 且自然的表达。
- 不因 Volume 较高而采用错误产品、错误介质或错误功能的关键词。
- 当前语言使用该语言自然表达；不要把外语关键词机械塞入正文。
- 品牌写法、产品型号和核心品类表达在全部导入文档中保持一致。

## 3. 全文统一

同时检查所有待导入 HTML，而不是逐文件孤立优化：

```bash
rg -ni "air release valve|air vent|automatic air vent|排空气阀|自动排空阀" <html目录>
```

- 同一概念只保留计划中的规范表达及确有语义用途的变体。
- 标题被 CMS 导入流程移除时，确保规范主关键词在正文靠前位置自然出现。
- 表格、型号列表、安全警告、标准名称和引用文档标题仅在语义完全等价时修改。
- 修改后再次搜索所有旧表达；逐项解释仍保留的例外，不能遗漏。

## 4. 内链

优先使用关键词 CSV 已维护的 `内链`。仅在维护 CSV 本身时才从数据库内容、栏目路径服务和现有静态页面确认目标 URL；不得根据文件名或关键词自行拼接第二套 URL。

- 链接到相关产品品类页、配套产品页或真正有帮助的专题页。
- 具体型号关键词的 `内链` 为空时不添加链接，等待对应产品详情创建后再回填 CSV。
- 使用描述性锚文本，避免“点击这里”。
- 对已确认的规范关键词，所有语义相同的可见文本精确匹配都使用同一目标链接，保证全文一致。不要处理标签属性、URL、代码或已有 `<a>` 内部文本，避免嵌套链接。
- 非精确同义词先按术语计划统一；无法自然统一的变体不强行链接。
- 不链接当前页面自身，不跨语言误链，不把产品型号链接到不对应的型号。
- 长篇技术内容可参考每 1000 词 3–5 个相关内链，但相关性优先，不把数量当硬指标。

## 5. 质量门槛

导入前确认：

- 规范词与 CSV 证据和产品事实一致。
- 所有文档的同一概念已统一处理。
- 关键词自然，不连续堆叠品牌、型号和品类词。
- 所有新增 `href` 均为真实、可访问、语言匹配的站内 URL。
- HTML 仍不含内联样式、文档私有 CSS 或无关结构变更。
