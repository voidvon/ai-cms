# 新增产品详情

把产品新增到当前 CMS 的 `product` 内容模型中。产品详情是栏目所属的内容条目，不是 MDX 文件，也不是新建一套产品专用页面代码。

## 开始前

1. 阅读仓库根目录 `AGENTS.md`，将本任务归类为“内容模型 + 栏目 + 静态生成”。
2. 阅读 [references/repository-rules.md](references/repository-rules.md)，确认当前字段、价格表规格提取、写入接口、URL 和验证规则。
3. 涉及产品选题、SEO、PDF 导入或内链时，阅读 [references/keyword-research.md](references/keyword-research.md)，按其中口径完成全目录关键词研究和型号边界审计。
4. 用户只提供型号/信息 ID、要求查找资料或 PDF、提供的 PDF 需要筛选，或最终正文需要合并文档时，完整阅读 [references/product-source-research.md](references/product-source-research.md) 并执行自动检索。不得把“请用户先找 PDF”作为默认前置条件。
5. 检查工作树；不要覆盖用户已有修改。
6. 修改 `data/site.sqlite` 前先备份。若只通过已运行 CMS 的 API/MCP 写入，也要确认目标是当前工作区数据库。

## 工作流

### 1. 选定产品与两阶段语言流程

- 用户已指定型号时直接处理；未指定时，从 `docs/关键词列表/按产品系列类型拆分/*.csv` 和 `docs/关键词列表/全部产品型号列表.md` 中筛选“明确型号 + 明确产品意图”的候选。
- 用户提供“信息 ID”时先只读查询该 ID 是否对应现有 `product` 条目：存在则以其型号、栏目和现有翻译作为更新基线；不存在则只把它作为任务目录标识，继续按型号查重或新建，禁止把未验证的 ID 强行写成数据库主键。
- 写内容前建立“产品主题契约”：记录唯一目标型号或经资料明确证明应共页的型号集合、允许的变体、默认排除的相邻型号，以及最终 `code`、`name`、`custom_url` 和询盘规格范围。用户指定单型号时，产品身份与转化字段（`code`、URL、名称/H1、摘要、SEO、询盘规格）的兄弟型号出现数必须为 `0`。正文、表格、图片替代文本、图注和内链锚文本默认也排除兄弟型号，但允许少量经逐项审查的比较、兼容性、选型分流或来源说明；每个例外都必须可验证、对用户有帮助且不暗示当前页同时销售该型号。
- 多型号 PDF 只是资料来源，不自动证明这些型号应在同一产品页。只提取主题契约覆盖型号的事实；将分析器报告中的兄弟型号缺失项记录为“按页面范围有意排除”，不能为了通过事实对账重新塞回正文。
- 关键词只证明搜索需求，不证明产品参数。优先读取对应国家/语言数据；无命中时才参考其他英文国家数据。
- 排除 `manual`、`guide`、`calculator`、`steam tables` 等资料或工具意图，以及只能承接泛家族概念的词。
- 产品内容一律先建立英文 `en` 母版。即使数据库默认语言是 `zh-CN`，也不得跳过英文阶段或先发布中文。
- 将一次完整多语言任务拆成两个必须分开的阶段：
  1. **阶段 A：英文母版。** 只研究、编写、导入、发布和验证 `en`；不得同时翻译其他语言。
  2. **确认门槛。** 英文公开页验证通过后，报告英文名称、摘要、SEO、正文结构、内链、规格、图片状态和 URL，然后停止并明确询问用户是否开始扩展全部启用语言。
  3. **阶段 B：多语言扩展。** 只有用户在英文母版完成后作出明确确认，才读取已验收的 `en` 母版并翻译全部启用语言。
- 用户在最初请求中写了“全部语言”“自动翻译”或类似授权，也不能越过确认门槛；确认必须发生在英文结果可供验收之后。用户只要求英文时，完成阶段 A 后直接交付，不主动执行阶段 B。
- 只为真实完成的语言写 `published` 翻译，不用英文或默认语言文本伪装本地化版本。
- 新建条目时，统一内容服务可能因数据库默认语言必填而要求 `zh-CN` 翻译记录。此时只允许创建未发布的技术性草稿壳：`name` 使用不需翻译的型号/代码，其他文案和正文保持空，`publish_status: draft`；不得复制英文名称、摘要、正文或 SEO，也不得生成中文公开页。

### 2. 查重并定位栏目

- 用内容 API/MCP 或数据库只读查询，按型号、名称、`code`、`custom_url` 检查 `content_product` 及 `content_product_translations`，避免同产品不同拼写或不同 URL 的重复条目。
- 从 `/products/` 栏目树中选择最具体且语义正确的现有 `list` 栏目。栏目必须绑定 `product` 内容模型。
- 复用 `columns.mjs`、`column-tree.mjs`、`column-paths.mjs`、`column-nodes.mjs` 的栏目和路径语义。不要自行拼接第二套产品路径。
- 只有确实缺少可表达的产品分类时才新增栏目；单一型号通常是内容条目，不是新栏目。

### 3. 自动检索产品资料、筛选 PDF 并建立事实边界

- 按 [产品资料与 PDF 自动检索](references/product-source-research.md) 依次检索本地资料、官方产品页、官方文档库和可验证的补充来源。用户未提供 PDF 时主动寻找；用户提供一份或多份 PDF 时仍要验证型号范围、文档类型、版本和信息增量，并自行选择最适合当前产品主题契约的最小资料集。
- 在任务临时目录保存 `research-report.md`、`source-manifest.json`、`pdf-selection.md`、`fact-matrix.md`、选用 PDF、SHA-256 和转换分析报告。搜索摘要和文件名只能用于发现来源，不能作为产品事实。
- 对候选 PDF 检查最终响应、`%PDF` 文件头、语言、文档编号、修订、目标型号正文覆盖和重复版本；为每份文件明确标记 `selected`、`supporting-only` 或 `rejected` 及理由。多型号 PDF 不自动扩大页面型号范围。
- 对 `selected` PDF 使用 `$convert-pdf-to-html`；再用 `$import-pdf-html-to-product-detail` 接入正文。复用这两个技能的分析、固定 HTML 结构、图片上传、备份和导入链路，不自行编写第二套转换或导入机制。
- 不从关键词 CSV 推断参数、材质、口径、压力等级、认证或下载 URL。
- 每个准备写入公开正文的能力、参数和适用条件都要进入 `fact-matrix.md`，带来源 URL/文件、文档编号、版本和 PDF 页码或网页章节。冲突优先按精确型号、官方性和较新修订消解；无法消解的事实不写入正文。
- 不把内部资料路径、搜索量、关键词筛选过程、数据库或仓库术语写入用户可见内容。
- 穷尽公开来源仍没有合适 PDF 时，可以只依据已验证网页资料编写产品介绍并记录资料缺口；不要伪造 PDF，也不要为填满页面而编造规格。

### 4. 组装 product 内容条目

使用当前内容模型字段，不新增产品专属硬编码字段：

- 基础字段：`column_id`、`custom_url`、`code`、`images`、`primary_image`、`spec_options_json`、`is_visible`、`is_featured_home`、`sort_order`、`created_at`。
- 翻译字段：`name`、`summary`、`content_html`、`template_data_json`、`seo_title`、`seo_description`、`publish_status`。
- `custom_url` 是可选的内容文件名，必须包含文件名，例如 `td52/index.html`；留空时由栏目 `detail_rule` 和内容 ID 生成 URL。
- `spec_options_json` 是字符串数组，每项是一条可展示、可用于询盘的规格文本。先确定当前详情页明确覆盖的型号集合，再从 `docs/价格汇总表.csv` 中逐型号精确提取；排除备件、套件和仅提及该型号的行，无精确整机记录时使用空数组。
- `publish_status` 只在内容完成并应公开时设为 `published`。同时设置 `is_visible: 1` 才能正常参与公开列表和生成。
- 首页展示使用 `is_featured_home`，不是旧项目的 `showInLatestProducts`/`launchDate`。是否推荐由用户需求和现有首页排序语义决定，不默认强制开启。

文案应自然覆盖型号词、产品类型和应用/选型意图。`name` 保持清晰产品名；站点或品牌后缀放入 `seo_title`。正文使用适合富文本字段的 HTML，不写 MDX/frontmatter。

英文母版是后续全部语言的内容真源：

- 先在 `en` 中确定产品名称、术语、事实、单位、表格、资料顺序、SEO 和内链信息架构。
- 英文资料直接整理为英文正文；非英文资料必须先准确转换为英文母版，再进入后续翻译阶段。
- 阶段 B 不得从某个译文继续转译另一语言，也不得把 `zh-CN` 当作中间母版。
- 英文母版验收后，除修正明确发现的事实或结构错误外，翻译阶段不得顺带改写英文内容。

更新已有产品或合并文档资料时，必须先读取目标语言当前的 `content_html`，识别原有产品简介并用事实矩阵复核。保留已验证且仍有价值的信息，修正冲突，删除无法核实的断言；禁止用新导入的文档正文覆盖简介，也不要在旧简介后机械追加一份重复研究摘要。最终正文按以下规则组装：

1. 依据 `fact-matrix.md` 编写原创“研究型产品介绍”，覆盖产品定位、关键特点与工程价值、典型应用/适用边界和可验证的选型提示；它始终是第一块可见正文。已有简介经复核后合并到这一块，不参与文档资料优先级排序。
2. 文档资料按“销售手册 → 技术资料 → 安装维修指南”排序；只导入 `selected` PDF，缺少某类资料时跳过，但不得改变其余资料的相对顺序。
3. 阶段 A 的目标语言固定为 `en`。阶段 B 翻译每种语言时必须以已验收的英文母版为源，保留型号、文档编号、标准、表格数值、单位、技术条件和安全含义；不得残留不必要的英文正文，也不得使用其他译文作为来源。
4. 介绍负责快速理解、差异化定位和选型导航；PDF HTML 负责完整技术表格、图纸、安装及安全细节。合并时删除介绍与文档片段间的大段重复，但不得删改文档中的安全条件。
5. 使用 PDF HTML 导入链路时，读取 `$import-pdf-html-to-product-detail`，保留原始转换结果，另建一个“研究型产品介绍 + 按优先级排列的全部文档片段”合并 HTML，并将其作为唯一的 `--html` 输入再执行默认替换；不能因整段替换丢失介绍或重复导入文档。

### 5. 写入数据库真源

- 首选当前 CMS MCP 的 `create_content_item`，或后台/API `POST /api/content-items/product`；更新时使用 `update_content_item` 或 `PUT /api/content-items/product/:id`。
- payload 必须使用 `{ base, translations }` 双层结构，并先读取当前内容模型字段，避免提交不存在的旧字段。
- 阶段 A 只写入或更新 `translations.en`，以及新建条目时为满足默认语言约束所必需的空白 `zh-CN` 草稿壳。不得预先创建带英文内容的其他语言记录。
- 阶段 B 必须重新读取已发布的 `translations.en` 作为母版，再逐语言写入同一个产品条目；不得创建重复基础记录。
- 没有可用 API/MCP 时，复用 `content-items.mjs` / `content-entries.mjs` 服务完成校验和写入。不要通过散乱 SQL 绕过规范化、多语言和字段校验。
- 新增产品通常不需要修改模板。产品详情模板必须始终显示数量选择和联系按钮，不得因 `spec_options_json` 为空或 `topPanel.ctaLabel` 缺失而隐藏；只有规格选择区可以在无规格时省略。若模板不满足该契约，修改数据库中的 `templates`/`template_versions` 及绑定，并复用现有 TSX 运行时；不得把源码目录或 `system/templates/` 当模板真源。

### 6. 处理图片

- 仅在用户提供图片或明确要求选用现有图片时处理图片；否则保持 `images: []`、`primary_image: ""`。
- 上述限制针对产品主图和图库；`selected` PDF 中属于文档正文的工程图、曲线图和示意图仍按 PDF 转换/媒体上传链路处理，不得误设为产品主图或图库。
- 使用后台媒体上传链路，将图片存入 `html/uploads/images/YYYYMM/`，数据库保存 `/uploads/images/YYYYMM/<file>`。
- `images` 是图库数组；`primary_image` 是主图。主图为空时服务会回退到 `images[0]`。
- 不写入旧 `public/images/`，不维护额外封面映射，不直接修补生成 HTML。

### 7. 优化英文母版与多语言内链

- 先搜索整个 `docs/关键词列表/按产品系列类型拆分/`，再定位主产品 CSV；不得只搜一个预判文件。分别报告目录原始命中次数、匹配行/文件数、主 CSV 去重后的有效查询数和可用内链目标数，禁止把任一内链数量表述成关键词数量。
- 为英文母版保存关键词计划，覆盖主词、产品类型词、拼写/空格/倒序变体、安装等意图变体、Volume、规范表达、放置位置、内链和不采用理由。错误拼写与不自然倒序词用于识别意图，默认规范化，不机械塞入正文。
- 从关键词 CSV 获取已有内链目标，但必须确认目标静态页或已发布内容真实存在；具体型号行的 `内链` 为空时不得自链接、回退品类或臆造 URL。关键词表中的失效、未生成或仅规划 URL 不得写入正文。
- 阶段 A 先审查英文母版正文的链接目标、出现语境和信息层级。阶段 B 的其他语言复用这套信息架构，只本地化锚文本和语言路径；不要为了增加数量额外堆叠相关型号。
- 锚文本必须符合目标语言的产品/工程术语，并自然嵌入完整句子。站内链接不得设置 `nofollow`、`sponsored`、`ugc` 或 `target="_blank"`。
- 西文及使用空格分词的语言必须检查链接前后的文本节点边界：链接前保留空格，链接后按标点规则处理，禁止出现 `word<a>` 或 `</a>word` 拼接。中文等不依赖空格分词的语言按本地排版处理。
- 修改复杂 `content_html` 时使用 `parse5` 等 HTML 解析器，并通过统一内容服务写回；不要用正则或字符串替换破坏文档结构。
- 只修改已发布且有真实本地化内容的语言。草稿空翻译不得用默认语言正文填充。

### 8. 阶段 A：验证英文母版并暂停确认

1. 重新读取条目并核对栏目、`en` 发布状态、英文名称、摘要、SEO、正文、图片和规格字段；逐项回查 `docs/价格汇总表.csv`。
2. 核对研究产物完整；报告主要官方来源、PDF 候选的选择/排除结论及理由、选用文件 SHA-256、仍未知事项和正文合并顺序。抽查公开正文事实均能回到 `fact-matrix.md`，未消解冲突写入数必须为 `0`。
3. 对照产品主题契约审计 `code`、URL、标题、摘要、SEO、正文可见文本、表格、图片 `alt`/图注、询盘规格和内链锚文本。产品身份与转化字段中的排除型号出现数必须为 `0`；正文每个兄弟型号引用都必须输出上下文、事实来源和保留理由，未审查或误导性引用数必须为 `0`。
4. 用 `buildContentDetailPathFromColumn` 对应的现有规则确认预期 URL，检查没有与既有内容冲突。更新 URL 或撤回既有语言前先记录旧公开路径；英文构建后确认旧英文路径已消失，并如实报告尚待完整构建清理的其他语言历史产物。
5. 审计关键词计划落地：报告正文词数、目标型号次数、身份字段排除型号次数、正文已批准引用次数、未审查引用次数、主规范词次数、意图覆盖、正文内链数和唯一目标数；说明哪些异常拼写仅被规范化而未原样插入。
6. 只生成并验证英文目标，优先运行 `npm --prefix system/server run build:static -- --language en --json`；如果使用单页生成，也必须显式指定 `--language en`。不要在阶段 A 运行会同时发布其他语言的翻译流程。
7. 通过英文公开路由抽查首页 `/`、联系栏目 `/contact-us/`、新增产品详情页、所属产品列表页和一个新闻详情页。
8. 检查列表页能进入产品、详情模板为数据库发布态 TSX 模板、图片存在且无旧路径、英文未从其他语言错误回退；分别抽查有规格和无规格产品，确认数量选择与联系按钮固定存在。检查英文站内链接目标、锚文本和边界空格，并确认没有 `nofollow` 或新窗口属性。
9. 更新已有英文正文或导入文档后，检查研究型产品介绍仍是第一块可见正文，介绍与 PDF HTML 没有大段重复，销售手册、技术资料、安装维修指南的顺序正确，且没有非必要的其他语言残留。
10. 报告条目 ID、栏目、英文 URL、产品主题契约、关键词四种统计口径、英文名称/摘要/SEO、资料来源与 PDF 选择、正文合并顺序、首页推荐状态、图片状态、历史路径状态和英文构建结果。
11. **强制停止。** 明确询问用户是否批准以当前英文母版扩展全部启用语言。在收到确认前，不得翻译、写入或生成任何其他语言；此暂停不属于任务失败或阻塞。

### 9. 阶段 B：确认后扩展全部启用语言

1. 收到确认后，重新读取数据库中已发布且已验收的 `translations.en`，将它作为本轮唯一翻译母版。
2. 实时读取 `languages.is_enabled = 1` 和 `language_sites`，确定除 `en` 外的全部目标语言、语言前缀、独立站输出目录和公开域名；不要硬编码旧语言清单。
3. 为每种目标语言独立翻译 `name`、`summary`、`content_html`、`seo_title` 和 `seo_description`。继承英文产品主题契约和已批准的兄弟型号引用清单，保留 HTML 结构、图片、目标型号、数值、单位、标准、安全含义和文档顺序；本地化术语、标点、内链锚文本与语言路径。身份字段的排除型号和未审查正文引用仍必须为 `0`，不得在译文中自行增加比较型号。
   - 简体中文 `zh-CN` 使用品牌专译“斯派莎克”。名称、摘要、正文可见文本、SEO、图片 `alt`、图注和内链锚文本中的 `Spirax Sarco` 必须全部替换为“斯派莎克”，不得保留 `Spirax Sarco（斯派莎克）` 等双写；验收时上述用户可见字段的 `Spirax Sarco` 残留数必须为 `0`。不要因此改写 `Spira-trol` 等产品系列名、型号、文档编号、URL 或其他未明确具有中文专译的商标。
4. 每种语言完成质量检查后再设为 `published`。未完成或无法可靠本地化的语言保持 `draft`，不得复制英文占位。
5. 通过统一内容服务逐语言写回同一条目。复杂 HTML 使用 `parse5`；不得通过正则破坏结构，也不得修改已验收英文母版。
6. 全部语言写入完成后只运行一次 `npm run build:site`。构建期间不要继续修改数据库，也不要并发启动第二个静态构建。
7. 逐语言检查公开详情页、所属列表页、SEO、图片、规格、数量和联系按钮；核对语言前缀/域名、内链目标、锚文本边界、标点，以及 `nofollow`、`target` 和错误语言回退均为零；额外确认 `zh-CN` 用户可见字段的 `Spirax Sarco` 残留数为 `0`，品牌统一为“斯派莎克”。
8. 最终报告英文母版状态、成功发布语言、保留草稿语言、各语言 URL、图片状态、首页推荐状态和完整构建结果。

## 禁止事项

- 不创建 `docs/<site>/products/**/*.mdx`、frontmatter、`models`/`cards` 入口或 Rspress 组件。
- 不新建产品专属渲染分支、路径算法、图片映射或规格选择脚本。
- 不恢复 `html`/`svelte` 模板引擎，或模板旧字段 `content`/`published_content`。
- 不直接批量修改 `html/` 页面；`html/uploads/` 中经媒体链路管理的上传文件除外。
- 不覆盖或无说明替换 `data/site.sqlite`，也不清理服务器运行数据。
- 不在英文母版验收前开始其他语言翻译；不把初始请求中的“全部语言”视为跳过阶段确认的授权。
- 不把多型号资料的标题或同表出现视为合并产品页的依据；不把目录命中数、去重关键词数和内链目标数混为一谈。
- 不把搜索摘要、文件名、聚合转载或关键词表写成产品事实；不下载伪装成 PDF 的 HTML，也不绕过登录、付费、验证码或许可限制。
- 不因用户没有提供 PDF 而默认暂停或要求其手动查找；先完成本地和公开网络检索。没有合适 PDF 时如实使用已验证网页资料，不伪造文档或参数。
