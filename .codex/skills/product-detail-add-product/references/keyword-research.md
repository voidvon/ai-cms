# 产品主题与关键词研究

## 1. 先锁定产品主题

在改数据库或写正文前记录：

- 目标型号或经资料证明应共页的型号集合；
- 允许的正式变体；
- 默认排除的兄弟型号，以及允许保留的引用类型；
- 最终 `code`、英文 `name`、`custom_url` 和 `spec_options_json` 覆盖范围。

用户指定单型号时，以单型号为最高约束。销售资料、技术资料或安装指南同时讲多个型号，只能证明资料可复用，不能证明页面应合并。

对 `code`、URL、名称/H1、摘要、SEO 和询盘规格采用硬性零容忍：不得出现不属于页面范围的兄弟型号。正文、表格、图片 `alt`、图注和链接锚文本采用“默认排除、逐项例外”规则。只有以下情况可保留：

- 明确比较材料、压力等级、接口或应用差异，能帮助选型；
- 说明真实兼容性、替代关系或不适用边界；
- 对共享资料标题、认证范围或图表来源作必要说明；
- 将用户分流到真实存在的兄弟型号页面。

每个例外必须有可验证来源、清晰上下文和保留理由，且不得把兄弟型号加入当前页的询盘规格或暗示当前页同时销售它。没有这些条件的出现应删除。验收时要求“身份字段出现数 = 0、未审查或误导性正文引用数 = 0”，而不是要求所有可见正文机械地绝对为零。

## 2. 搜索整个关键词目录

先搜索整个 `docs/关键词列表/按产品系列类型拆分/`，同时覆盖官方拼写及空格、连字符、下划线和已知本地变体，再选择主产品 CSV。不要先认定一个 CSV 后只在该文件中搜索。

可使用 `rg -ni` 获取原始证据，再用支持 BOM 和 CSV 引号的解析器读取包含 `Keyword` 字段的文件。分类规则、人工摘要、自动候选和进度文件用于审计分类过程，不能重复计作独立 SEO 关键词；Volume、Intent 和 `内链` 以正式产品系列/类型 CSV 为准。

## 3. 分开四种统计口径

必须分别报告，不能用一个数字代替另一个：

1. **目录原始命中次数**：搜索表达在整个目录中的字面出现次数。
2. **匹配行与文件数**：用于说明证据分布。
3. **有效查询数**：在正式产品 CSV 中按规范化关键词去重后的查询表达数量。
4. **可用内链目标数**：非空、非当前页且经验证存在的唯一 `内链` URL 数量。

例如“18 次目录命中、7 个有效查询、1 个内链目标”是三个不同事实。不得把“1 个内链”表述成“只找到 1 个关键词”。

## 4. 建立语言独立的关键词计划

英文母版至少记录：原词、规范表达、关键词类型、Volume/Intent、使用位置、内链目标和处理理由。覆盖：

- 最高相关且自然的产品主词；
- 型号 + 产品类型词；
- 品牌/型号倒序、空格和拼写变体；
- installation、manual 等意图变体；
- 品类词及其已维护内链。

错误拼写、错误型号空格和不自然倒序词用于理解需求，默认统一为官方型号与自然语言，不为了“精确匹配”损害可读性。资料/安装意图可由准确的 SEO、标题层级和对应章节承接，不把 `manual` 查询误当成新产品。

具体型号关键词的 `内链` 为空时，不链接当前页自身，不回退到品类页。只有 CSV 已维护、语义相关、语言匹配且实际存在的目标才可写入正文。

## 5. 导入前后验收

导入前保存关键词计划到任务临时目录。导入后统计：正文词数、目标型号次数、身份字段排除型号次数、正文已批准兄弟型号引用次数、未审查引用次数、主规范词次数、意图章节覆盖、正文链接数、唯一链接目标数、异常属性数和失效目标数；同时保存批准引用的上下文、来源和理由。

不以固定密度为目标；技术表格、型号、文档编号和安全说明中的重复不等同于堆砌。多型号 PDF 对账产生的兄弟型号“缺失”应记录为范围内有意排除。阶段 B 的每种语言重新建立本地关键词计划，但必须继承英文产品主题契约。
