# 产品资料与 PDF 自动检索

本流程在用户只提供产品型号或信息 ID、没有提供 PDF 时执行；用户已经提供 PDF 时也要执行，用于判断文件是否真的覆盖目标型号、是否为最佳资料以及是否还缺少必要的官方资料。目标不是收集尽可能多的文件，而是建立可追溯的事实边界，并选出足以支撑英文产品详情的最小资料集。

## 1. 固定检索输入与产物

先只读确认用户给出的信息 ID 是否为现有 `product` 条目 ID；存在时读取其产品主题、栏目和现有正文，不存在时只将该值用于任务目录命名，不把它当数据库主键。再读取产品主题契约、现有产品记录和本地关键词结果，整理官方型号、系列名、旧称、带空格/连字符的写法、产品类型词及已知文档编号。不要用未经证实的兄弟型号扩展检索范围。

在 `tmp/product-<信息ID或规范型号>/research/` 保存：

- `research-report.md`：可人工审阅的产品资料整理文档；
- `source-manifest.json`：来源 URL、标题、发布者、抓取日期、语言、型号范围、资料类型和访问结果；
- `pdf-selection.md`：PDF 候选、版本、选择/排除结论及理由；
- `fact-matrix.md`：准备写入正文的事实、数值、适用型号、来源 URL、PDF 页码或网页章节；
- `downloads/`：最终选用 PDF；文件名使用规范型号、文档编号和语言，不沿用无意义下载名；
- 每份选用 PDF 的 SHA-256，以及 `$convert-pdf-to-html` 生成的分析报告路径。

`research-report.md` 至少包含产品身份、资料摘要、来源分级、PDF 选择结论、已核实能力与规格、型号边界、冲突与处理、仍未知事项、建议正文提纲。报告是任务证据，不直接整段复制到公开产品页。

## 2. 检索顺序

1. 搜索本地 `../source-markdown`、当前产品正文、同系列已发布内容、已有下载记录和用户提供文件。
2. 搜索 Spirax Sarco 官方全球站、官方国家/地区站及官方文档库。组合查询官方型号、系列名、产品类型、已知文档编号，并分别加入 `filetype:pdf`、`technical information`、`installation and maintenance instructions`、`brochure` 等意图。
3. 从官方产品页继续发现其下载链接；解析真实链接并验证响应，不只记录搜索结果页或搜索摘要。
4. 官方当前站不足时，再查官方旧站/其他地区站、官方可验证 CDN 或档案链接。
5. 仍不足时才使用授权经销商或可靠行业站点作为线索；产品参数必须尽量回到官方资料交叉验证。普通 PDF 聚合站、转载页和无出处营销文不得作为唯一技术事实来源。

可用任一当前环境允许的网页搜索或 HTTP 工具。访问公开网页、跟随重定向和下载公开 PDF 属于此技能的默认研究步骤，不要因为用户没有手动给 PDF 就暂停。遇到登录、付费、验证码、许可限制或无法安全确认的下载时不得绕过，并在报告中记录。

## 3. 来源与事实分级

按以下优先级判断同一事实：

1. 当前官方且精确覆盖目标型号的技术资料或安装维修指南；
2. 当前官方产品页、销售手册或型号族资料；
3. 官方其他地区/较旧版本资料；
4. 授权经销商或可靠行业资料；
5. 搜索摘要、聚合转载和无明确版本资料，仅作发现线索，不写成已确认事实。

`fact-matrix.md` 每行记录：事实或参数、值与单位、目标型号范围、来源级别、URL/文件、文档编号、修订日期或版本、PDF 页码/网页章节、是否进入正文。网页摘要、文件名和搜索关键词不能代替正文证据。

若来源冲突，优先采用精确型号、较新修订和更高来源级别的资料；不能可靠消解时保留冲突记录并从公开文案中删除该断言。不同口径、连接方式、阀内件或执行机构的参数不得合并成一个无条件数值。

## 4. PDF 验证与选择

对每个候选执行以下检查：

- 最终响应成功，文件头确为 `%PDF`，不是返回 PDF 扩展名的 HTML 错误页；
- 记录最终 URL、内容长度、SHA-256、语言、页数、标题、文档编号、修订/发布日期；
- 提取文本确认目标型号及允许变体确实出现，并判断它们是正文适用对象还是仅在兼容性、目录、页脚中被提及；
- 判断资料类型：销售手册、技术资料、安装维修指南或其他；
- 比较重复文件、语言版本和修订版本，避免转换同一内容的多个镜像；
- 多型号 PDF 必须逐页标记目标型号适用范围，不因同表或同标题出现而扩大产品主题契约。

按“精确型号覆盖、来源权威、版本较新、信息增量、英文母版可用性”选择最小资料集。通常按“销售手册 → 技术资料 → 安装维修指南”排序；不是每类都必须有。精确技术资料优先于泛系列手册，安装指南不能替代产品定位和主要选型参数，营销手册不能替代安全与安装条件。

`pdf-selection.md` 对每个候选标记：

- `selected`：转换并合入正文；
- `supporting-only`：只用于事实交叉核验，不整份转换；
- `rejected`：重复、型号不符、版本较旧、来源不可信、语言不适合英文母版或没有信息增量。

必须写明选择理由。用户提供的 PDF 也没有自动优先权；若不适合，应保留文件并解释为何改选另一份。若穷尽公开来源仍没有合适 PDF，但官方网页足以建立准确简介，可继续生成“研究型产品介绍”并明确没有文档 HTML；不得伪造 PDF 或要求用户重复做已经能够自动完成的搜索。

## 5. 转换、合并与去重

1. 对每份 `selected` PDF 调用 `$convert-pdf-to-html`，保留源文件 SHA-256、分析报告和转换产物；不为 `supporting-only` 或 `rejected` 文件生成 HTML。
2. 先依据 `fact-matrix.md` 编写原创英文产品介绍，不逐句复制网页。介绍依次覆盖：产品定位、关键特点与工程价值、典型应用/适用边界、可验证的选型提示。只有资料充分时才增加参数摘要表。
3. 更新已有产品时，把现有简介逐条对照事实矩阵；保留已验证且仍有价值的信息，修正冲突内容，删除无法核实的断言。不得简单在旧简介后重复追加研究摘要。
4. 将“研究型产品介绍”作为正文第一块，再按“销售手册 → 技术资料 → 安装维修指南”追加转换后的文档片段。保留 `$convert-pdf-to-html` 的原始产物不变，另建用于导入的合并 HTML；其 `<body>` 先放介绍，再放全部 `.pdf-document` 文档包装器，并保证所有本地图片路径仍能从合并文件位置解析。将该合并文件作为 `$import-pdf-html-to-product-detail` 唯一的 `--html` 输入，防止默认整体替换 `content_html` 时丢失介绍或因重复传入原文件而重复文档。
5. 对介绍与 PDF HTML 去重：介绍负责快速理解、差异化定位和选型导航；文档片段负责完整技术表格、图纸、安装与安全细节。相同参数只在介绍中摘要一次，不复制整张表，也不删减文档中的安全条件。
6. 合并后的每个产品事实都必须能回到 `fact-matrix.md`；关键词仅决定表达和信息架构，不得成为事实来源。

最终正文保持一个产品详情语义：只使用产品详情模板提供的页面 H1；导入片段默认移除独立 PDF 的 `document-header`、`title-band` 和 `document-footer`。产品介绍使用正常富文本章节，PDF 片段继续保留 `.pdf-document` 固定结构。

## 6. 验收门槛

进入英文写入前确认：

- `research-report.md`、`source-manifest.json`、`pdf-selection.md` 和 `fact-matrix.md` 均存在；
- 所有公开参数均有来源，未消解冲突和未知事项没有被写成确定结论；
- 每份选用 PDF 均通过文件类型、型号范围、版本和 SHA-256 检查；
- PDF 选择覆盖了所需信息且没有无增量重复文件；
- 研究型产品介绍位于文档片段之前，现有已验证简介没有被意外覆盖；
- 介绍与文档片段不存在大段重复，文档顺序正确；
- 兄弟型号、文档编号、数值、单位和适用条件通过产品主题契约审计。

英文验收报告中列出主要官方来源、所选/排除 PDF、选择理由、仍未知事项和最终正文合并顺序。不要把内部临时路径、检索过程或来源分级写进公开正文。
