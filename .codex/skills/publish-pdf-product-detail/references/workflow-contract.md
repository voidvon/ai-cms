## 输入清单

开始前收集：

- 产品 ID，或新产品的型号、名称与目标栏目；
- PDF 文件及其文档类型：销售资料、技术资料、安装维修指南；
- 产品关键词 CSV；
- 是否保留旧文档和旧图片；
- 目标语言范围，默认取 `languages.is_enabled = 1`；
- 用户提供的主图或语言专用图片；
- 已有产品简介、SEO、规格、图片、栏目和 URL 快照。

缺少产品事实时停在内容准备阶段，不从关键词 CSV 补造参数。
已有产品未显式提供关键词 CSV 时，可根据 ID 对应的型号、英文名称、栏目和 URL 在关键词目录中自动定位；多个候选意图冲突时再请求确认。

## 阶段交接物

### PDF 转换阶段

每份 PDF 交付：

- 一个原始转换 HTML；
- 一个同级 `assets/` 图片目录；
- 一份由 PyMuPDF 生成且带源文件 SHA-256 的 `report.json` 和 `report.md`；
- 页级文本、理解预览、表格候选和 PDF→HTML 事实候选对账结果；
- 文档类型和顺序；
- PDF 页数、文档编号、版本及未能确认的内容；
- 桌面、手机和打印验证结果。

原始转换 HTML 只作真值基线。英文术语优化在副本上进行。

### 英文母版阶段

交付：

- 已组装的英文 HTML；
- 英文关键词计划；
- 规范术语表；
- 已验证内链表；
- 英文产品名称、摘要、SEO 标题与描述；
- 文档结构、图片、数值和标准校验结果。

### 产品图片阶段

交付：

- 每张输入图的原路径、格式、像素、源文件大小和转换结果；
- 上传后的媒体 ID、`/uploads/images/...` 路径和文件大小；
- 最终主图、图库顺序及追加或替换策略；
- 图片是真实提供、AI 编辑还是 AI 生成；
- 实际使用的英文提示词文件、重绘模式、尝试次数和视觉验收结论；
- 被替换但为回滚暂时保留的旧媒体清单。

### 多语言阶段

每个语言交付：

- 本地化名称、摘要、正文、模板数据和 SEO；
- 从英文术语到本地术语的映射；
- 本地关键词计划；
- 本地化锚文本和带正确语言前缀的内链；
- 发布或保持草稿的结论。
- 英文母版哈希、批次草稿和实际使用的 provider；provider 探测失败时保留不含密钥的错误摘要。

## 英文母版验收门

英文必须先通过以下检查：

1. 第一段是已有英文产品简介或其经用户授权的改写。
2. 文档顺序为销售资料、技术资料、安装维修指南。
3. HTML 使用固定 PDF 文档框架，不含正文 `<style>`、内联 `style` 或 `<link>`。
4. 表格数值、单位、型号、标准、文档编号和安全意义与 PDF 一致。
5. 图片具有真实 `width`、`height`，本地资源存在且裁切完整。
6. 英文主关键词来自产品意图，已覆盖名称、摘要、SEO、首段和必要标题，但没有堆砌。
7. 内链目标存在、相关、不是当前页，且符合关键词 CSV 和站点路径规则。
8. 同一规范词在相同语义下保持一致；资料意图词没有冒充产品主词。

任何一项失败都禁止启动其他语言翻译。

## 新产品与已有产品

### 已有产品

先读取所有翻译并保存快照。复用基础记录、栏目、URL、规格和主图。除用户明确要求外，不改变首页推荐状态。

### 新产品

先在临时文件中完成英文母版，不为取得 ID 提前创建空壳产品。英文通过后生成真实的 `zh-CN` 名称和草稿摘要，再通过内容服务创建草稿产品。取得 ID 后导入英文正文，并在全部目标语言完成前保持不可公开状态。

## 产品图片与 AI 生成

### 用户提供的产品图片

默认链路为：源图预检 → `$redraw-product-images` 生成并保存提示词 → 保真重绘 → 源图对比验收 → CMS 图片优化器 → `product_cover` 媒体上传 → 内容服务更新 `images` 和 `primary_image`。不得另写一套格式转换或上传路径。

支持格式以 CMS 当前 `UPLOAD_ALLOWED_EXTENSIONS` 为准。上传服务负责 HEIC/HEIF 解码、EXIF 方向校正、压缩和 WebP/JPEG/PNG 候选择优；工作流只校验和编排，不承诺强制输出某一种扩展名。

多图时第一张新图默认作为主图，其余按输入顺序加入图库。默认追加并去重；替换图库和保留原主图必须显式选择。旧媒体在全流程构建和路由验证前不得删除，以免数据库回滚后引用丢失。

### 重绘与 AI 图片

用户提供产品源图时，完整发布工作流默认调用 `$redraw-product-images` 的 `catalog-redraw`，并由该 Skill 生成实际英文提示词、调用 `$imagegen`、输出无新增文案的 `16:10` 网站产品预览图并执行真实性验收。用户明确要求保持原图时才跳过。

从零生成图片是可选分支，不是缺图时的自动兜底。没有真实源图时，只有用户明确要求才生成不承载产品事实的场景图。

- 可生成：不承载技术事实的应用场景、营销背景或辅助视觉。
- 可编辑：背景、画布和非产品环境；必须逐图核对产品主体不漂移。
- 禁止生成或重绘后当作事实：真实产品主图、接口结构、工程图、尺寸图、铭牌、认证标识、安全图示和性能曲线。
- AI 生成或编辑结果必须保留源图、提示词、模式和验收标记，先保存到工作区并验收，再走与真实产品图相同的媒体上传链路。
- 营销场景图默认只加入图库；设为主图需要用户明确要求。

### PDF 文档图片

英文导入负责首次上传文档图片。导入完成后，以数据库中已经标准化为 `/uploads/...` 的英文正文作为结构母版。

其他语言翻译只修改文本和本地化属性，默认保留相同图片 URL 和尺寸，不再次运行会重复上传相同图片的导入流程。语言专用图片必须有明确需求，并单独记录媒体差异。

清理旧图片时只使用媒体服务的引用检查；禁止直接删除磁盘文件。

## 多语言验收门

对每个启用语言检查：

1. 直接从英文母版翻译，不含来自中文或另一译文的链式误差。
2. 文档结构、表格行列、图片、数值、单位、标准和文档编号与英文一致。
3. 产品术语符合本地工程表达，品牌和型号不被翻译。
4. 关键词结合英文搜索意图进行本地化，不机械保留英文词。
5. 内链沿用英文信息架构，但锚文本和路径前缀符合该语言。
6. 西文链接前后文本节点保留必要空格；站内链接无 `nofollow`、`target` 等属性。
7. SEO、摘要和正文均为真实本地化内容；不完整版本保持 `draft`。
8. 非中文正文不残留中文句号、中文说明或默认语言回退内容。
9. 产品主图和图库在所有语言中保持同一基础记录；语言专用图片必须有明确理由并记录差异。

## 写库、构建与回滚

全部输入预检通过后、首次写库前使用 SQLite 一致性备份方式，例如 `.backup` 或 `VACUUM INTO`。同一工作流的图片、英文正文和 PDF 附件步骤复用该基线备份，并执行 `integrity_check`；不要在 WAL 未检查点时只复制主数据库文件，也不要为前置检查失败创建无效备份。

原始 PDF 使用 `purpose: pdf_document` 上传并写入英文翻译的 `attachments_json`。按 `sales_brochure`、`technical_information`、`installation_guide` 分类；只有存在真实本地化 PDF 时才为其他语言创建单独附件，否则沿用英文 fallback。

中间导入统一使用 `--no-build`。所有语言写完后先运行数据库审计，通过后仅执行一次 `npm run build:site`，再运行静态审计。

最终报告至少包含：

- 备份路径和数据库完整性结果；
- 产品 ID、栏目、URL、可见性和推荐状态；
- 英文母版关键词及关键词 CSV；
- 已发布、草稿和停用语言；
- 每语言正文内链数和异常数；
- 图片复用或语言专用图片差异；
- 产品主图和图库来源、顺序、转换结果及 AI 使用情况；
- 每张重绘图对应的源图、英文提示词、模式、尝试次数和验收结论；
- 静态构建结果与公开路由抽查结果。
