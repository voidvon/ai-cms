# 重绘产品图片

把本 Skill 作为“真实产品图到可发布图片”的专业处理层。必须先完整读取并使用 `$imagegen`；本 Skill 负责产品事实、提示词、模式和验收，`$imagegen` 负责实际生成或编辑。格式转换、压缩和 CMS 上传不在这里实现。

需要编写提示词或判断验收规则时读取 [提示词与验收契约](references/prompt-and-validation-contract.md)。

## 核心约束

- 真实产品主图必须有用户提供或可验证的源产品图。没有源图时不得生成一个看似真实的产品并设为主图。
- 默认把源图作为 `edit target`，不是仅供风格参考。不得擅自改变产品角度、轮廓、比例、接口、法兰、螺纹、紧固件、执行机构、显示面板、材质、颜色、铭牌、品牌或型号。
- PDF 和产品记录用于确认名称、型号及用途，不用于补造源图中看不到的结构。隐藏面、模糊文字和缺失部件不得由模型猜测。
- 每次调用前必须生成并保存实际使用的英文提示词，同时给出简短中文意图摘要。提示词是正式交付物，不得只存在于对话或工具参数中。
- 默认输出固定为横向 `16:10` 网站产品预览图，交付画布为 `1600 × 1000`。图片模型负责重绘，最终比例和画布尺寸使用本 Skill 的确定性脚本校正。
- 禁止在图片上新增标题、副标题、卖点、参数、徽章、按钮、水印或任何营销文案。只保留源产品本体上原本可见的 Logo、铭牌和型号；看不清的文字不得补写。
- 原图永不覆盖。每次生成使用带模式和版本号的新文件名，并记录源图、提示词、输出图和是否通过验收。
- 默认只生成一张候选图；验收失败时根据单一问题定向重试，最多两次。仍无法保持产品真实性时停止，不把结果交给 CMS。

## 处理模式

### `catalog-redraw`

默认模式，用于网站产品主图预览。把源图转换为横向 `16:10` 构图，保持原视角和产品主体，重建为干净、均匀、真实的工业目录摄影；使用白色或用户指定的纯色背景，不增加场景道具、任何文案、阴影特效或额外部件。

### `background-only`

只清理或替换背景，产品像素和轮廓尽量不变。适合原图产品已经清晰，仅背景杂乱的情况。使用 `precise-object-edit` 提示，不要求重新设计产品光照。

### `transparent-cutout`

输出透明产品切图。遵循 `$imagegen` 的透明图片规则：默认先生成纯色键控背景并使用其本地移除工具；复杂反光、玻璃、液体或软边对象需要 CLI 原生透明时，必须按 `$imagegen` 要求先取得用户确认。

### `industrial-scene`

把可验证产品放入合理的蒸汽或工业应用环境，只作为图库或营销辅助图。保持源图可见角度，不生成隐藏结构，不添加不可验证的接管、仪表、认证标识或性能文字；默认不得设为产品主图。

## 工作流

### 1. 收集和检查输入

收集产品 ID、源产品图片、目标模式、主图或图库用途、背景要求及输出位置。通过产品内容服务读取产品名称、型号、现有图片和栏目；只提取提示词需要的可验证信息。

用 `view_image` 查看每张本地源图，记录：主体角度、可见接口、主要部件、颜色、材质、标识位置、原背景及任何不得变化的细节。无法看清时写入“不允许猜测”，不要推断。

### 2. 生成提示词包

为每张图创建独立目录，默认使用：

```text
tmp/product-image-redraw/<产品ID>/<源文件名>/
```

运行提示词生成脚本；`--invariant` 按实际观察重复传入：

```bash
node .codex/skills/redraw-product-images/scripts/build-prompt.mjs \
  --source <源产品图> \
  --product-id <ID> \
  --product-name "<英文产品名称>" \
  --product-code "<型号>" \
  --mode catalog-redraw \
  --invariant "Preserve the exact visible flange count and positions." \
  --invariant "Do not change the visible label placement." \
  --out <输出目录>/prompt-en.txt
```

打开生成的提示词，确认其中没有源图和产品资料无法支持的视觉描述。把英文原提示词原样交给 `$imagegen`，不得再临时追加会改变产品结构的创意要求。

### 3. 执行重绘

按 `$imagegen` 的 built-in edit 流程处理：先用 `view_image` 让本地源图进入上下文，明确标记为 `edit target`，再调用图片编辑。输出是项目资产时，将选定结果从默认生成目录复制到上述工作区目录；不要覆盖源文件。

`catalog-redraw` 和 `background-only` 必须要求保持原视角。`industrial-scene` 如需要改变透视或展示隐藏面，应停止并请求更多角度的真实产品图。

图片模型输出后，使用确定性脚本统一为 `1600 × 1000`。默认使用白色画布和 `contain`，保证产品完整且不裁切：

```bash
node .codex/skills/redraw-product-images/scripts/normalize-preview-image.mjs \
  --input <图片模型输出> \
  --out <输出目录>/preview-1600x1000.webp
```

透明切图增加 `--transparent` 并输出 PNG 或 WebP。脚本只调整方向、尺寸、比例、画布和编码，不添加文字或重新生成产品内容。

### 4. 验收输出

先运行技术检查：

```bash
node .codex/skills/redraw-product-images/scripts/inspect-image-pair.mjs \
  --source <源产品图> \
  --output <标准化后的16比10结果> \
  --prompt <提示词文件> \
  --mode catalog-redraw \
  --product-code "<型号>"
```

再使用 `view_image` 逐张对比源图和输出，按参考契约检查产品真实性。脚本通过不代表视觉真实性通过；任何部件数量、接口位置、铭牌内容、品牌、型号或比例漂移都必须判定失败。

失败时只针对一个问题修改提示词，例如“恢复原图中左侧唯一法兰的位置和比例”。每次重试都保存新提示词和新输出。不得用局部正确掩盖其他结构漂移。

### 5. 交付

只交付通过技术检查和人工视觉对比的 `1600 × 1000` 结果。报告：产品 ID、模式、源图、英文提示词、中文摘要、输出图、尝试次数、未改变的关键细节和验收结论。

接入 `$publish-pdf-product-detail` 时，把通过验收的 `catalog-redraw` 或 `background-only` 输出作为产品主图候选，把 `industrial-scene` 作为图库候选，再交给其 `set-product-images.mjs`。不得在本 Skill 中直接修改数据库、媒体记录或静态页面。

## 失败处理

- 源图缺失、严重模糊或只有局部时，停止真实产品主图重绘；可请求更清晰或更多角度的图片。
- 图片工具不可用时遵循 `$imagegen` 的回退规则，不私自改用未授权模型或 API。
- 无法确认型号或外观对应关系时，不把 PDF 中同系列示意图当作当前型号源图。
- AI 输出未通过时保留失败文件用于比较，但不得上传 CMS 或设为主图。
