# Spirax 专题内容简报

## 总则

使用本 skill 时，默认用中文输出分析、计划、执行说明和最终总结；面向访客的专题内容则先生成英文 `en` 版本并作为多语言母版，除非用户明确指定其它顺序。

本 skill 用于把任意 Spirax CMS 专题请求转成可落地的 SEO 工作流：搜索意图、关键词地图、网上与本地资料依据、文章结构、图片候选、内链建议、英文 `en` CMS 安全富文本母版，以及必要时的多语言补全与静态生成验证。

把用户确认设为英文母版与多语言扩展之间的硬门槛。整理并验证完 `en` 后，先向用户提交英文结果、验证摘要和待扩展语言范围，然后停止并请求确认。只有在此之后收到用户明确的“确认”“可以扩展全部语言”或等价指令，才可开始逐语言关键词研究；每种语言完成本地关键词映射后，才可翻译、写入或生成该语言。用户在最初任务中提出“最终发布全部语言”，不能替代英文母版完成后的再次确认。

不要把 skill 固定成“疏水阀专用”。它必须按专题 ID、栏目、关键词 CSV 和资料证据判断专题类型。专题可能是产品系列、应用场景、服务、行业、问题解决方案、指南或下载入口。

不要手改生成后的 `html/` 页面作为真源。若用户要求写入 CMS，应先检查当前专题/内容服务和数据库结构，通过现有数据库/API/静态生成链路保存与验证。

## 前台内容边界

关键词、用户意图、搜索行为、内容缺口、页面定位和内链策略只属于分析简报或执行说明，不能原样写进前台富文本、栏目摘要、SEO description、卡片摘要或结构化数据。

面向访客的专题正文必须像一篇完整的专题页，而不是内容策划稿。禁止在发布正文中出现这类表达：

- “经过分析”“分析结果”“根据关键词列表”“用户搜索量表明”
- “从关键词需求看”“用户会搜索”“搜索词中包含”“承接某某需求”
- “长尾词”“关键词线索”“关键词覆盖”“SEO 上建议”
- “本轮资料覆盖不足”“后续资料页补充对象”“不在总专题中写入”
- “正式发布到 CMS”“source-markdown”“内部链接交由栏目路径服务维护”
- “面向已经明确搜索……的用户”
- 英文正文中同样禁止出现 “according to our keyword research”“search volume shows”“to target this keyword”“SEO recommendation”“content gap”“publish to the CMS”“internal workflow” 等研究和执行过程话术。

清理对象是上述分析过程、SEO 执行过程和内部工作流话术，不是承载正文的内容结构。表格、选型矩阵、参数对比、型号索引、列表、FAQ、图片、内链和资料入口都是正常专题内容，默认保留；专题中使用表格通常有助于选型、比较和快速浏览。

禁止因为表格、列表或某个章节中出现了分析话术，就删除整个表格、模块或章节。应只改写有问题的标题、句子或单元格，保留其中对访客有用的产品事实、应用信息、型号、链接和结构。例如：

- 不写：“经过分析，用户搜索量显示安全阀选型需求较高。”
- 改写：“安全阀选型需结合介质、设定压力、排放能力和连接方式。”
- 不写：“根据关键词列表，FT14、FT44 和 FT46 是重点型号。”
- 改写：“FT14、FT44 和 FT46 可按压差、口径、连接方式及排量要求进行比较。”
- 表格单元格中若出现“应与安全阀页面形成内链”，只把它改写为自然的应用说明并保留原有链接，不得删除该行或整张表。

除非用户明确要求，或内容存在事实错误、无依据重复、失效链接等可验证问题，不要减少原有表格数、表格行数、图片数、有效内链数和正文模块数。若确需删除，先说明具体依据和影响范围。

可以保留产品型号、英文实体词和资料类型词，但要改写成自然的产品说明或资料入口。例如：

- 不写：“承接 FT14 manual / FT14 installation 等需求。”
- 改写：“可进入 FT14 产品页查看参数、安装说明和资料文件。”
- 不写：“FT44 等长尾词目前适合链接到分类页。”
- 改写：“FT44、FT46、FT47 等型号可先查看浮球式蒸汽疏水阀产品分类，具体参数以已发布资料为准。”

如果用户明确要求“先修改中文版本”，可覆盖默认的 `en` 优先顺序，并优先清理中文 `topic_profiles`、`column_translations` 和相关内容卡片摘要。不要只改专题正文；还要检查 meta 描述、masthead 摘要、关联卡片和 JSON-LD 是否仍暴露分析话术。

## 资料优先级

除非用户另有指定，按以下顺序取证。网络检索是默认资料搜集渠道，不需要等到本地资料不足才使用：

1. 用户明确给出的关键词 CSV。若未给出，则根据专题 ID、栏目名、`topic_keyword`、路由、相关术语，从 `docs/关键词列表/按产品系列类型拆分/` 推断最匹配的 CSV。
2. 本地结构化资料：`/Users/yytest/Documents/projects/source-markdown`，优先查产品/专题相关 markdown、PDF 提取文本、元数据和索引。
3. Spirax Sarco 官方网站及其可公开访问的地区站、产品页、技术资料、PDF 和知识内容，优先 `https://spiraxsarco.com/` 和 `https://www.spiraxsarco.com/global/en-US`。
4. 搜索引擎可发现的可信网络资料，包括制造商资料、行业标准、专业技术机构和高质量工程参考；记录页面标题、URL、来源主体和访问日期，并交叉核实关键技术说法。
5. 本地全局素材：`/Users/yytest/Documents/projects/some-global-assets`，包括 PDF、图片和可复用视觉素材。

网上搜集资料时，优先官方一手来源；关键参数、型号适用范围、安装方向、安全要求和维护结论不得仅依据论坛、聚合页、无署名转载或搜索摘要。来源之间冲突时，以当前官方资料为准并在简报中标记差异；无法核实的说法不得写入访客正文。

关键词 CSV 是 SEO 需求证据，不是堆砌词库。优先处理高搜索量、意图明确、商业价值高、与当前专题强相关的词。实体词不要只写裸型号或裸术语，应尽量扩展成用户真实搜索短语，例如“型号 + 产品类型”“型号 + manual / installation / pdf”“品牌 + 型号 + steam trap”等。

## 工作流

1. 定位 CMS 对象：专题 ID、当前栏目名、路由、语言、`topic_profiles` 富文本字段、发布状态，以及本次是只做分析还是需要保存。默认先锁定 `en` profile、英文栏目翻译、英文路由和英文站点输出目录。
2. 读取关键词 CSV，按专题类型聚类：
   - 主关键词
   - 实体关键词：产品/型号、应用、行业、问题、服务、技术、文档类型等
   - 信息型关键词
   - 商业/交易型关键词
   - 长尾修饰词：manual、installation、PDF、选型、维护、故障、价格、供应商、应用、对比等
3. 用 `rg` 优先检索本地资料，搜索中文名、英文名、路由片段、专题关键词、CSV 高频实体词。不要假设所有专题都是产品页。
4. 用 `find`、`file`、文件名检索图片/PDF。记录素材路径、主题、建议 alt 文案。已有插图不要随意移除；如果图片不足，追加候选或占位，方便用户后续上传。
5. 同步检索 Spirax Sarco 官网和可信网络资料，补充产品能力、型号适用场景、行业背景、标准、安装与维护依据；保存可追溯 URL，并对会进入正文的关键事实做交叉核实。
6. 先形成中文执行简报，再撰写英文 `en` 富文本母版。简报里要区分“资料证据”和“写作建议”，英文母版要单独完成事实、术语、语法、SEO、内链和访客可读性验收。
7. 富文本使用 CMS 安全 HTML：语义化标题、段落、表格、列表、figure/img、描述性锚文本。禁止 inline script；不要大段复制来源内容。
8. 保存或生成前，扫描拟发布字段，确保内部分析词没有进入访客可见内容：
   - `topic_profiles.intro_html`
   - `column_translations.summary`
   - `column_translations.seo_description`
   - 相关内容卡片的 `summary` / `seo_description`
   - 生成后的 meta、masthead、JSON-LD、正文和卡片摘要
9. 对已有正文做清理时，保存前后统计表格、表格行、图片、链接、H2/H3 和主要模块数量。若任务只是移除分析过程话术，这些结构数量原则上不得下降；逐处改写命中的文本，不要按父级节点整块删除。
10. 完成并验证 `en` 后，向用户提交英文标题、摘要、正文结构、SEO 字段、主要资料依据、图片与内链情况、验证结果，以及查询到的待扩展语言清单；随后停止，明确询问用户是否确认扩展全部语言。
11. 只有收到英文结果提交之后的新一轮明确确认，才查询全部启用语言及其语言代码、地区、域名或子目录配置。确认前不得预先生成其它语言草稿。
12. 对每种目标语言重新研究本地化关键词：先查本地关键词 CSV 和项目关键词资料，再查该语言的 Spirax Sarco 官方地区站、当地搜索结果和可信行业来源；形成该语言的关键词映射并记录证据。不得把英文关键词直接翻译后当成本地关键词研究结果。
13. 每种语言只有在本地关键词映射完成后，才把已确认的 `en` 母版本地化为该语言，并据此调整标题、摘要、H1/H2、正文术语、表格、FAQ、图片 alt、锚文本、SEO 字段和结构化数据，随后执行内链与静态生成验证。

## 多语言本地化关键词研究

把每种语言和目标市场作为独立的 SEO 研究单元。即使两种语言接近，或多个地区使用同一种语言，也要根据 `language_sites`、目标域名、地区和实际搜索表达判断能否复用关键词，不要默认共用同一套词。

对每种目标语言依次执行：

1. 用 `rg --files docs/关键词列表` 和专题实体词查找匹配该语言或市场的关键词 CSV；读取真实数据列，保留搜索量、意图、排名或其它已有指标，不要推测不存在的数据。
2. 若本地没有匹配 CSV 或覆盖不足，使用目标语言检索 Spirax Sarco 官方地区站、当地搜索结果、相关搜索、搜索建议、可信制造商和行业技术资料。能使用关键词数据工具时，补充当地搜索量、竞争度和意图；不能取得数据时明确标记“无可验证搜索量”，不得编造数值。
3. 对照英文母版的主题、产品实体、应用、问题、服务和资料类型，建立“英文概念 → 当地主关键词 → 常用变体/同义词 → 搜索意图 → 证据来源”的映射。
4. 区分品牌、型号、标准号等不可翻译实体与需要本地化的产品类型、应用、问题和文档词。保留真实使用的英文型号短语，但不要用英文词替代当地用户普遍使用的行业术语。
5. 选择一个主关键词和必要的次关键词、实体词、信息词及商业词；过滤歧义词、低相关词、其它产品词和仅由机器直译产生的生硬表达。
6. 先完成关键词映射，再改写内容。关键词应自然影响页面定位和表达，不得机械替换、堆砌或改变已确认英文母版中的技术事实。

每种语言的关键词映射至少记录：语言/地区、主关键词、次关键词、实体与长尾词、搜索意图、数据或来源、采用位置、排除词及排除原因。缺少本地证据时，仍可基于官方当地术语做谨慎本地化，但必须在执行简报中标记证据不足和后续复核项。

## 写入 CMS 时的规则

- 英文 `en` 是默认内容母版：先完整打磨并验收 `en` 的标题、摘要、富文本、SEO 字段、图片 alt、内链和结构化数据，再开始其它语言。
- 未完成或未验收 `en` 母版时，不要批量生成其它语言；用户明确要求跳过英文或指定其它母版语言时除外，但仍应在选定母版完成后请求确认再扩展。
- `en` 母版验收后先暂停并请求用户确认。确认前不得创建、翻译、覆盖、写入或发布任何其它语言的 `topic_profiles`、栏目翻译、SEO 字段或关联卡片内容。
- 用户最初要求“全部语言”只表示最终范围，不视为确认；必须在用户看到英文结果后再次获得明确确认。
- 获得确认后，查询并复核全部启用语言；为每种语言完成本地关键词研究和关键词映射后，再逐一补齐 `topic_profiles`，不要遗漏英文或只改中文。
- 不得只翻译英文 Title、description、H1/H2、FAQ 和锚文本；应根据该语言已验证的本地关键词、搜索意图和行业用语进行本地化改写。
- 如果用户只要求中文，仍要检查中文专题根栏目、专题详情栏目和中文关联卡片，不要留下旧的分析型摘要。
- 多语言版本可以保留高价值英文实体关键词，尤其是 CSV 中的品牌、型号、manual、installation、PDF 等搜索短语。
- 站内链接要按语言站点路径处理：子目录语言应使用对应前缀，如 `/fr/...`、`/es/...`；独立站语言按当前站点配置处理。
- 产品型号或其它实体如果有详情页，应链接到详情页；如果没有详情页，不要造不存在 URL，可链接到最接近的分类页、服务页或专题页，并用文字说明用于选型/替代确认。
- 内链锚文本应是有意义的短语，不要只用裸型号。例如优先“FT14 疏水阀”“Spirax Sarco FT14 steam trap”，而不是只写“FT14”。
- 高频型号/实体应集中放入选型表、型号矩阵或推荐列表，避免全文机械重复。
- 清理分析型表达时，保留已有表格结构、表头、行、链接和有效事实；优先做单元格级或句子级改写。
- 静态资源路径不要硬编码成本机临时地址。富文本里优先使用项目可解析的 `/uploads/...` 或 CMS 媒体路径，让运行时/静态构建处理正式资源地址。

## 内链检查

生成或更新正文后，必须检查内链质量：

- 统计正文链接数、唯一链接数、图片数、H2/H3 数量。
- 对重点实体词检查是否出现在锚文本中，尤其是用户点名的型号或 CSV 高频词。
- 对站内链接确认能解析到当前语言的静态文件、目录或本地服务 200 响应。
- 对没有详情页的实体，不要把分类页链接误报为详情页链接。
- 链接结构要覆盖：上游知识页、产品分类页、重点产品详情页、相关服务页、相关系统/解决方案页。

## 静态生成验证

涉及专题富文本发布后，优先使用项目现有静态生成链路验证，不要直接改 `html/`：

- 单页函数可能不会自动切换语言输出目录；多语言验证优先使用整站静态生成入口的对应 sections，例如 `buildStaticSite({ sections: ['topic-pages'] })`。
- 输出目录以 `language_sites.output_dir` 为准，例如 `html`、`html/fr`、`html_ru`、`html_ar`、`html_zh_cn`。
- 默认先只生成并验证 `en` 专题页；确认英文正文、meta、JSON-LD、图片和内链正确后，向用户汇报并暂停。收到用户明确确认后，才生成其它启用语言。
- 验证目标专题页是否在每个语言目录生成，并抽查正文结构、图片、内链，以及该语言关键词映射在 Title、description、H1/H2、正文、FAQ 和锚文本中的自然应用。不得用机械重复次数代替本地化质量检查。
- 如果用户正在访问 `http://127.0.0.1:1231/...`，实际响应可能来自根目录 `html/`。当中文语言配置输出到 `html_zh_cn` 时，只生成 `zh-CN` 不一定会更新 1231 页面；应确认服务实际读取目录。需要更新 1231 看到的中文页面时，必须通过现有静态生成链路把中文输出到根 `html/`，不要手改 `html/`。
- 若临时调整 `language_sites.output_dir` 来重写根 `html/`，构建完成后必须恢复原配置，并再次验证服务响应。
- 针对分析话术的发布前/发布后检查可以使用精确词组扫描，例如：

```bash
rg -ni "经过分析|分析结果|根据关键词列表|用户搜索量|从关键词|覆盖 [0-9]+ 条关键词|承接|长尾词|source-markdown|正式发布|本轮|面向已经明确搜索|不在总专题|according to (our )?keyword research|search volume shows|to target this keyword|SEO recommendation|content gap|publish to the CMS|internal workflow" html/topics html_zh_cn/topics
```

## 输出格式

执行简报默认使用中文，英文 `en` 富文本母版作为独立交付内容，并采用以下结构：

```markdown
**专题**
- CMS ID：
- 当前标题：
- 搜索意图：
- 推荐页面定位：
```

## CMS 约束

- 保持 CMS 的栏目、内容模型、模板、静态生成架构，不要做一次性静态页面。
- 不要把 `html/` 当作内容真源。
- 保存专题内容时优先使用现有专题/内容 API 或数据库真源；模板改动才使用数据库 TSX 模板链路和 `modify-cms-template` skill。
- 不要新增专题专用硬编码渲染逻辑。
- 关键词密集页面要自然写作，把型号/实体集中到表格、选型指南、FAQ 或内链清单中。
- 页面角色要匹配栏目树：专题 hub 应引导到子专题、产品、服务和知识内容；窄专题应回答具体意图并做上下游链接。
- 未经栏目、profile 和关键词证据支持，不要把专题固定成产品页、文章页、下载页或行业页。
