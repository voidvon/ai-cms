# 专题树功能设计

## 结论

专题功能使用现有 CMS 的「栏目树 + 内容模型 + 数据库模板绑定」实现。

- 栏目树负责专题层级、URL、导航、列表页、详情页和模板绑定。
- `topic` 内容模型负责专题内容数据，包括主关键词、关键词组、SEO 信息、正文、关联产品、关联资料和模块配置。
- 不新增独立专题路由，不手改 `html/`，不绕开现有静态生成链路。

## 为什么用栏目树

当前关键词已经存在明显树形关系。例如：

- 疏水阀
  - 浮球式疏水阀
  - 热动力疏水阀
  - 恒温/平衡压力疏水阀
  - 倒吊桶疏水阀
- 减压阀
  - 先导式减压阀
  - 直接作用式减压阀
  - 减压站
- 过滤器
  - Y 型过滤器
  - 篮式过滤器
  - 蒸汽/洁净蒸汽过滤器
- 冷凝水泵
  - 泵疏水阀/APT
  - 冷凝水回收泵组
- 止回阀
  - 圆盘止回阀
  - 对夹式止回阀
- 汽水分离器
  - 蒸汽分离器
  - 压缩空气分离器

这些结构天然适合栏目树。栏目树可以表达父子专题，并让每个专题拥有独立 URL 和模板绑定。

## 内容模型字段

已新增系统内容模型：

- 模型编码：`topic`
- 模型名称：`专题`
- 主表：`content_topic`
- 翻译表：`content_topic_translations`

核心字段：

- `column_id`：所属专题栏目
- `code`：专题编码
- `topic_type`：专题类型，例如 `product_family`、`product_type`、`solution`
- `parent_topic_code`：父级专题编码，方便导入或外部同步
- `primary_keyword`：主关键词
- `keyword_group`：关键词组
- `related_product_categories_json`：关联产品分类
- `related_products_json`：关联产品
- `related_resources_json`：关联资料
- `related_tools_json`：关联工具
- `related_industries_json`：关联行业
- `module_config_json`：专题页面模块配置
- `template_variant_key`：模板变体标识
- `name`、`summary`、`content_html`、`seo_title`、`seo_description`、`publish_status`：多语言内容字段

## URL 建议

建议创建一个专题根栏目：

```text
/topics/
```

然后按关键词树建立子栏目：

```text
/topics/steam-traps/
/topics/steam-traps/float-steam-traps/
/topics/steam-traps/thermodynamic-steam-traps/
/topics/pressure-reducing-valves/
/topics/pressure-reducing-valves/pilot-operated-pressure-reducing-valves/
```

详情规则可以先使用：

```text
{id}.html
```

如果每个专题栏目只维护一条专题内容，可以后续再通过模板或栏目首页策略把专题内容直接渲染到栏目首页。

## 建专题的筛选标准

优先建专题：

- 有搜索量或关键词数量明显较高。
- 能对应明确产品族、产品类型或解决方案。
- 能支撑独立内容，包括选型、工作原理、关联产品、应用场景、FAQ 和资料下载。
- 可以作为其它页面的内部链接枢纽。

暂不单独建专题：

- 只有规格、尺寸、材质、压力等级、连接方式等属性词。
- 只有单个型号且无法支撑独立内容。
- 搜索意图更像资料查询、价格查询、说明书查询，而不是产品/方案页面。

这些词更适合作为 `keyword_group`、筛选项、FAQ、产品参数或资料模块内容。

## 初始种子

初始专题树数据见：

```text
docs/关键词列表/按产品系列类型拆分/专题树种子.json
```

这份 JSON 先作为建栏目和录入专题内容的依据，不直接写数据库。后续如果需要批量导入，可以基于这份结构再写导入脚本，调用现有栏目和内容 API。

## 后续增强

建议后续分三步做：

1. 在后台提供专题栏目批量创建/导入能力。
2. 为 `related_products_json`、`related_resources_json` 增加可视化选择器。
3. 在数据库模板中新增专题列表和专题详情模板变体，通过现有模板绑定和静态生成发布。
